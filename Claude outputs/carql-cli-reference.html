carql Command Reference

Every command, every flag, and how they connect. The whole tool is two verbs — train writes a run folder, show reads one — and everything else is a variation on reading runs and tracks.

Orientation

Mental model

Three kinds of things on disk. Commands either create them or read them.

Tracks — tracks/*.json

Walls, ordered reward gates and a start pose in world units. Made by build (drawn), track import (from a PNG), or converted by hand (classic). Referenced everywhere by name (classic, track_1) or by path.

Runs — runs/<name>/

One training session. Self-contained: it carries its config and a copy of its track, so a run never depends on files that may change later. Referenced by name.

Checkpoints — ep_NNNNNN.pt

Weights saved every train.checkpoint_every episodes, plus the config, the episode/frame counters and the greedy evaluation score at that moment. Selected with a checkpoint spec.

runs/classic-dueling_per/ ├─ config.toml exact config the run used ├─ track.json copy of the track ├─ checkpoints/ │ ├─ ep_000050.pt every checkpoint_every episodes │ ├─ ep_000100.pt │ └─ … ├─ latest.pt most recent weights ├─ best.pt best greedy evaluation so far ├─ metrics.csv one row per training episode ├─ eval.csv greedy eval every eval_every episodes └─ log.txt
Naming. Without -r, a run is called <track>-<variant>: classic-dueling_per, classic-ddqn, classic-dqn, classic-ppo. Training into an existing name is refused unless you pass --resume.
Orientation

Recipes

The four things you will actually do, end to end.

First run, then watch it

carql train                          # Dueling DDQN+PER on classic → runs/classic-dueling_per/ (~15–30 min)
carql show                           # newest run, all checkpoints, starts on the latest

Training prints one line every 50 episodes; the eval N gates / M laps at the end of the line is the greedy policy from the start line, and it is what the viewer's timeline bars show.

The demo: from disaster to drifter

carql show classic-dueling_per --start first      # open on checkpoint #1
# then in the window: → next checkpoint · digits 1–9 jump to 10–90 % · End = final model
carql race classic-dueling_per -k spread:6        # or let six stages of training race at once

Architecture tournament

for c in dqn ddqn dueling_per ppo; do carql train -c $c; done
carql plot                                        # learning curves, all runs
carql race classic-dqn classic-ddqn classic-dueling_per classic-ppo -k best

Each preset gets its own run folder because the default name includes the variant. Same track, same budget, same physics — only the agent differs.

A new track

carql build                                       # click a centerline, scroll for width, S saves tracks/custom-….json
carql play -t custom-0910-1120                    # feel it with the arrow keys
carql train -t custom-0910-1120 -c ppo            # → runs/custom-0910-1120-ppo/
carql show classic-dueling_per -t custom-0910-1120   # or drop an old policy onto it
Command

carql train

Train an agent and write a run folder. Blocks until the episode budget is reached; Ctrl+C saves latest.pt and exits cleanly.

Synopsis 
carql train [-c PRESET] [-t TRACK] [-r NAME] [-n EPISODES] [--resume] [--set section.key=value …]
FlagDefaultMeaning
-c, --config PRESETdefault.tomlAgent preset from configs/: dqn, ddqn, dueling_per, ppo — or a path to your own .toml. A preset is layered on top of configs/default.toml; the shipped ones only change the [agent] section.
-t, --track TRACKclassicTrack name in tracks/ or a path to a track .json. Same as --set env.track=….
-r, --run NAME<track>-<variant>Run folder name under runs/. Refused if it already has checkpoints, unless --resume.
-n, --episodes N3000Total episode budget (cumulative when resuming). Episodes get long once the car laps, so the budget in frames grows over a run; 3000 episodes ≈ 3 M frames for DQN.
--resumeoffContinue an existing run from its latest.pt, using the run's stored config. A different -c on the command line is ignored with a note; only -n and -r are taken from the command line.
--set section.key=valuerepeatable—Override any config key: --set train.n_envs=32 --set env.reward_crash=-80 --set agent.hidden=[128,128]. Booleans accept true/false; lists are written without spaces.
Examples 
carql train -c ppo                                   # → runs/classic-ppo/
carql train -t track_1 -r t1-fast -n 5000            # named run on another track
carql train -r classic-dueling_per --resume -n 6000  # continue to 6000 episodes total
carql train --set agent.per=false --set agent.eps_end=0.02
carql train -c dqn --set train.seed=1 -r classic-dqn-s1   # second seed, separate folder

What a log line means: ep 1200 | 916k frames | ret 501 | score 92 | laps 1.7 | len 977 | crash 0.73 | eps 0.050 | loss 0.045 | 1.7k fps | 9.0 min | eval 216.9 gates 3.00 laps. Everything before eval is a 100-episode training average (cars spawn at random gates and explore with ε-greedy, so score undercounts what the greedy policy can do). eval is the greedy policy from the start line and feeds best.pt and the viewer's timeline.

Command

carql show

Watch one run drive. Loads the selected checkpoints, draws the training timeline along the bottom, and lets you switch between them live.

Synopsis 
carql show [RUN] [-k SPEC] [-t TRACK] [-s START] [--speed X] [--no-rays]
FlagDefaultMeaning
RUNnewest runRun name (or path to a run folder). Without it, the most recently modified run under runs/.
-k, --checkpoints SPECallWhich checkpoints to load into the timeline — see checkpoint specs. every:250 thins a long run.
-t, --track TRACKthe run's trackDrive on a different track than the one trained on. Physics come from the checkpoint, the geometry from the track.
-s, --start STARTlatestCheckpoint to open on: an episode number (nearest wins), first, or latest.
--speed X1Simulation steps per rendered frame (60 frames/s). 0.5 is slow motion, 4 fast forward; +/- change it live.
--no-raysrays onStart with the 16 sensor rays hidden (V toggles them).
Examples 
carql show                                   # newest run, latest checkpoint
carql show classic-ppo -s first              # open on the very first checkpoint
carql show classic-dueling_per -k every:250  # fewer dots on the timeline
carql show classic-dueling_per -s 1200 -t track_1 --speed 2

The HUD shows run and algorithm, checkpoint index and its eval score, gates/laps/steps, speed, drift, the action being taken, the last reward and the episode return. The bar chart at the bottom left is the Q-value (or, for PPO, the action probability) of each of the nine actions, with the chosen one highlighted: L R A B = left, right, accelerate, brake; AL AR BL BR combinations; - coast. Keys are listed under Keyboard.

Command

carql race

Several checkpoints and/or runs drive the same track at the same time as ghost cars, with a live leaderboard. Checkpoints from one run make a training-progress race; best checkpoints from several runs make a tournament.

Synopsis 
carql race RUN[:SPEC] [RUN[:SPEC] …] [-k SPEC] [-t TRACK] [--speed X] [--no-respawn]
FlagDefaultMeaning
RUN[:SPEC]one or more—Run names. A run may carry its own spec after a colon (classic-ppo:best, classic-dqn:200,1500); runs without one use -k.
-k, --checkpoints SPECspread:6Spec applied to runs given without their own. best turns a list of runs into a tournament.
-t, --track TRACKfirst run's trackRace on another track.
--speed X1Simulation steps per frame.
--no-respawnrespawn onBy default a crashed car reappears on the start line after ~1 s and its crash is counted. With this flag everyone stays dead until the last car is done, then the field resets.
Examples 
carql race classic-dueling_per                       # 6 checkpoints spread over training
carql race classic-dueling_per -k 100,500,1000,latest
carql race classic-dqn classic-ddqn classic-dueling_per classic-ppo -k best     # tournament
carql race classic-ppo:best classic-dueling_per:spread:3 -t track_1

The leaderboard ranks by lap progress (laps, then gates, then distance to the next gate) and shows crashes. Tab moves the inspection focus — rays, Q-values and the highlighted next gate follow the focused car. Cars from different runs must share the car physics; the first run's config is used for the arena.

Command

carql build

Track builder. You draw a centerline with the mouse and pick a width; walls (the contour of the rasterised stroke) and evenly spaced gates are generated live.

Synopsis 
carql build [TRACK] [--size WxH] [--width W]
FlagDefaultMeaning
TRACKnew trackAn existing generated track to edit (name or path). Hand-coded tracks like classic have no centerline and cannot be edited — import a PNG or draw a new one.
--size WxH1260x700World size for a new track, in world units. The classic track is 1260×700 with a 25×15 car; keep that scale unless you also change [car].
--width W90Initial road width. Classic is ~85 wide, track_1 ~50 (tight).

New tracks save as tracks/custom-MMDD-HHMM.json; the name is shown in the top-left panel. The start is control point 0 (yellow); the blue arrow is the start pose. T drops a car onto the track you are drawing so you can test-drive it before saving. Full key list under Keyboard.

Command

carql play

Drive a car yourself with the arrow keys — the fastest way to feel a track's difficulty and the reward numbers.

Synopsis 
carql play [-t TRACK]
FlagDefaultMeaning
-t, --track TRACKclassicTrack name or path.

↑ accelerate, ↓ brake, ←/→ steer; combinations map to the same nine discrete actions the agent has. The car never fully stops (minimum speed, as in the original) and drifts when turning above speed 5. The HUD shows the per-step reward, so you can see what the agent is being paid for.

Command

carql track

Track utilities: import a drawing, inspect, list, render.

Synopsis 
carql track import PNG [--name N] [-o OUT] [--height H] [--gate-spacing S] [--open] [--invert] [--reverse]
carql track info TRACK
carql track list
carql track preview TRACK [-o OUT.png]
Subcommand · flagDefaultMeaning
import PNG—A drawn road, bright on a dark background (like the original Track.png). The stroke is skeletonised to recover the centerline and the distance transform gives the width; the result is a regular generated track you can edit in build.
--name Nfile stemTrack name.
-o, --out OUTtracks/<name>.jsonOutput path.
--height H700World height the image is scaled to (keeps the car proportion consistent with the classic track).
--gate-spacing S60Distance between gates in world units. Fewer gates = sparser reward.
--openclosed loopThe stroke is a point-to-point course; the last gate is the finish line.
--invertoffDark road on a bright background.
--reverseclockwiseDrive counter-clockwise.
info TRACK—Size, wall and gate counts, start pose, approximate lap length.
list—One line per track in tracks/.
preview TRACK [-o]<track>_preview.pngStatic PNG with walls (red), gates (green, first one yellow) and the start (blue dot) — handy for checking an import without opening a window.
Examples 
carql track import assets/track_1.png --name track_1
carql track import sketch.png --gate-spacing 45 --reverse
carql track preview track_1 -o /tmp/t1.png
Command

carql runs

List every run under runs/ with its algorithm, track, checkpoint range and best evaluation.

Synopsis

classic-dueling_per          dqn  track=classic       60 checkpoints (ep 50..3000), best eval 216.9 gates / 3.00 laps @ ep 1200
classic-ppo                  ppo  track=classic       60 checkpoints (ep 50..3000), best eval 246.1 gates / 4.00 laps @ ep 2200
Command

carql export

Simulate a race headlessly (no window) and write a self-contained HTML replay: canvas rendering, scrubber, speed control, leaderboard, trails. One file, no dependencies, send it to anyone.

Synopsis 
carql export RUN[:SPEC] [RUN[:SPEC] …] [-k SPEC] [-t TRACK] [--steps N] [-o FILE] [--no-respawn]
FlagDefaultMeaning
RUN[:SPEC] …—Same run/spec syntax as race.
-k, --checkpoints SPECspread:6Spec for runs without their own.
-t, --track TRACKfirst run's trackTrack to simulate on.
--steps N1800Simulation steps to record; 60 steps = 1 s of replay. 1800 ≈ 30 s ≈ 150 KB.
-o, --out FILEreplay.htmlOutput file.
--no-respawnrespawn onAs in race.
Examples 
carql export classic-dueling_per -k spread:6 --steps 2400 -o replays/timeline.html
carql export classic-dqn:best classic-ppo:best -o replays/final.html

Inside the viewer, E does the same for the last 60 seconds you just watched, into replays/<run>-<timestamp>.html.

Command

carql plot

Learning curves: training score, greedy evaluation, episode length and return — one line per run, so several runs overlay for comparison. Needs matplotlib (pip install -e ".[plot]").

Synopsis 
carql plot [RUN …] [-o FILE.png]
FlagDefaultMeaning
RUN …all runsRun names to overlay. No argument (or all) plots every run.
-o, --out FILE.pngopen a windowWrite a PNG instead of opening an interactive window.
Examples 
carql plot
carql plot classic-dqn classic-ddqn classic-dueling_per classic-ppo -o tournament.png
Reference

Checkpoint specs

The value of -k / --checkpoints, and what follows the colon in RUN:SPEC. Episode numbers snap to the nearest saved checkpoint.

latestThe most recent weights (latest.pt). Default for show's start.
bestHighest greedy evaluation so far (best.pt). Use for tournaments.
allEvery checkpoint in the run. Default for show.
1200The checkpoint nearest to episode 1200.
100,500,1000,latestAn explicit list; latest and best may appear in it.
spread:6Six checkpoints evenly spaced from first to last. Default for race and export.
every:250Every checkpoint whose episode is a multiple of 250.
Reference

Config keys

Everything in configs/default.toml, overridable with --set section.key=value. A run stores the resolved config in its folder, and every checkpoint carries a copy.

[car] — physics, in world units per simulation step
KeyDefaultMeaning
length / width25 / 15Car rectangle, along and across the heading. Collision box and drawn size.
max_speed12.5Top speed. Turn radius at top speed is ~60 units, less than the classic road width.
min_speed0.78The car never stops — braking floors at this speed (original behaviour).
acceleration0.156Speed gained per step while accelerating.
brake_factor2.0Braking = brake_factor × acceleration.
friction0.98Speed multiplier per step when coasting.
turn_rate0.2Radians per step at full steering authority.
steer_full_speed5.0Below this speed, steering authority scales down linearly (no turning on the spot).
drift_gain1.0Sideways momentum added per turn step. 0 = pure grip, 1 = the original Tokyo drift.
drift_friction0.87Decay of drift momentum per step.
drift_min_speed5.0No drift below this speed.
[env] — track, sensors, rewards, episode limits
KeyDefaultMeaning
track"classic"Track name or path (-t sets this).
n_rays / fov / ray_length16 / 360 / 600Distance sensors: count, angular coverage in degrees, maximum range. Changing them changes the observation size — start a new run.
gate_lookahead2Bearings to the next N gates are part of the observation (lets the car anticipate corners).
max_steps2000Episode length cap.
stall_steps300Episode ends if no gate is passed for this many steps.
reward_gate5.0Bonus for crossing the next gate in order.
reward_step-0.01Cost per step.
reward_progress0.01Per world unit of forward progress towards the next gate (dense shaping; ~0.12/step at top speed).
reward_crash-50.0Penalty for hitting a wall. Must dominate the dense progress reward: at −5 a fast-and-crashy policy is nearly as good as a careful one and DQN learns exactly that.
reward_lap20.0Bonus for completing a lap (closed track) or finishing (open track).
speed_bonus0.0Optional per-step bonus proportional to speed.
random_starttrueTraining only: spawn at a random gate so the whole track is seen early. Evaluation and the viewer always start on the start line.
start_jitter_deg5.0Random heading jitter at spawn (training); evaluation uses at least 3°.
[agent] — network and learning
KeyDefaultMeaning
algo"dqn"dqn (with the flags below) or ppo.
hidden / activation[256,256] / "elu"MLP layers. The dueling head adds two 256-wide streams on top.
lr / gamma2.5e-4 / 0.99Adam learning rate, discount.
double / dueling / pertrue / true / trueDQN variants: Double DQN target, dueling value/advantage head, prioritised replay. The presets are just combinations of these.
per_alpha / per_beta0 / per_eps0.6 / 0.4 / 1e-3Prioritisation exponent, initial importance-sampling exponent (annealed to 1), priority floor.
per_clip5.0|TD error| is clipped to this for priorities (0 = off). Without it the −50 crashes make PER sample only the newest transitions.
reward_scale0.1Rewards are multiplied by this before entering the replay buffer, keeping TD errors near unit size. Logged and displayed rewards are unscaled.
buffer_size / batch_size200000 / 128Replay capacity (transitions) and minibatch size.
learning_starts5000Frames of random play before the first gradient update.
updates_per_step4Gradient updates per batched environment step (64 cars → 4 updates of 128 samples).
n_step3Multi-step returns.
target_update / polyak500 / 0.005Gradient updates between hard target-network copies; target_update = 0 switches to Polyak averaging with this rate.
eps_start / eps_end / eps_decay_frames1.0 / 0.05 / 500000ε-greedy schedule, linear in frames (not episodes).
grad_clip / huber10.0 / falseGradient-norm clip; Huber instead of MSE loss.
rollout_steps / ppo_epochs / minibatches128 / 4 / 8PPO only: steps per car per rollout, epochs over each rollout, minibatches per epoch.
clip / gae_lambda / entropy_coef / value_coef0.2 / 0.95 / 0.01 / 0.5PPO only: clipping range, GAE λ, entropy and value-loss weights.
[train] — schedule and bookkeeping
KeyDefaultMeaning
run""Run name (-r); empty = <track>-<variant>.
n_envs64Cars simulated in parallel. More cars = more data per gradient update.
total_episodes3000Episode budget (-n).
checkpoint_every50Episodes between checkpoints → 60 dots on the timeline for a default run.
eval_every / eval_envs50 / 8Greedy evaluation from the start line every N episodes, over this many jittered cars; feeds best.pt.
log_every50Episodes between log lines.
seed0Seeds numpy, torch and the environments.
device"auto"auto resolves to CPU — these networks are too small for a GPU to pay off.
threads0Torch CPU threads (0 = torch default). Set to 1–2 when running several trainings side by side.
